Part two · Improve the journey

Child care service prototype

1. Provider applicant + ministry review

Guided forms reuse provider information, flag missing answers and let the ministry request specific corrections. Review actual answers and resubmission history.

ApplicantMinistry

Working browser-local prototype. Open both views in this browser to share saved state. Form acceptance does not issue a licence or funding award. Grant forms support preparation only.

2. Family search + provider inbox

Families find and compare care, review exactly which child details they share, and apply to a fictional connected provider. Switch to that provider to respond, then see the response in the family view.

Download working local app

Working Node 24 + SQLite backend included in the download. Run locally using the setup instructions. Nine researched listings and two fictional connected providers. Real providers do not receive demo applications.

Current integration boundary: the family and provider inbox share a working local database. Applicant and ministry forms share browser storage. Those two systems are not yet connected, and this public page does not host the family backend.

The complete service we are working toward

Provider applies → Ministry reviews and approves → Provider workspace is provisioned → Family applies → Provider reviews
Target architecture: shared provider identity and case records, with role-based access and auditable state changes.

The intended outcomes are fewer repeated entries, fewer incomplete applications and faster, better-informed review. These are hypotheses for a pilot; no reduction in processing time or decline rates has been measured.

Next steps: connect approved provider records to family search, implement verified identities and secure document storage, confirm licensing and grant rules with service owners, and test with ministry staff, providers and families.
